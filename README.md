# Visual ESP Overlay — demo 0.2

C++20 / Windows x64 / DirectX 11 / DirectComposition / Dear ImGui / CMake.

Проект создан для первой стадии: полностью отдельное окно с тестовыми объектами и камерой. **Все объекты синтетические. Подключение к Dead by Daylight отсутствует.** Версия `10.2.2` в `offsets.json` — метка будущего источника, а не заявление о проверенной совместимости. Чтение памяти, поиск процесса и реальные смещения не реализованы.

## Сборка в Visual Studio 2022

Требуются Windows 10/11 x64, Visual Studio 2022 с компонентом **Desktop development with C++**, MSVC v143, Windows SDK 10/11, CMake 3.24+ и Git. При первом конфигурировании нужен HTTPS-доступ к GitHub для ImGui 1.91.9b и nlohmann/json 3.11.3. Обе зависимости закреплены по точным upstream commit; проверка HTTPS остаётся включённой.

В Developer PowerShell for VS 2022, из корня репозитория:

```powershell
cmake --preset vs2022-x64
cmake --build --preset release --parallel 2
ctest --preset release
.\build\vs2022\Release\VisualESPOverlay.exe
```

Или откройте корень через **File → Open → Folder**, выберите preset `vs2022-x64`, соберите `VisualESPOverlay` и выберите его startup target. Можно открыть сгенерированный `build/vs2022/VisualESPOverlay.sln`.

`offsets.json` копируется рядом с exe после сборки. Этот файл обязателен при запуске. `config.json` появляется там же после нажатия **Save**. Расположение файлов вычисляется по пути exe и не зависит от текущего рабочего каталога. Для сохранения настроек каталог exe должен быть доступен для записи. Runtime MSVC устанавливается вместе с Visual Studio или Microsoft Visual C++ Redistributable x64.

## Демонстрация

Окно покрывает основной монитор. DirectComposition использует swap chain с premultiplied alpha; фон очищается в `(0, 0, 0, 0)`. При недоступности аппаратного D3D11 используется WARP. Отдельное верхнее окно не внедряется в другие приложения. Оно рассчитано на рабочий стол и оконный/borderless режим; exclusive fullscreen не является поддерживаемым сценарием.

Демосцена содержит четырёх survivors, killer, два generators, два hooks и два exit gates. Камера и часть персонажей движутся. Рамки персонажей строятся по точкам ног и головы, а дистанция считается от камеры в метрах. Цвет survivor/killer настраивается; генераторы обозначены `G`, крюки `H`, ворота `E`. Постоянный индикатор `DEMO - NO GAME CONNECTION` остаётся виден даже при выключенных визуальных элементах.

Меню изначально открыто. При скрытом меню окно пропускает клики; открытое меню включает ввод. Меню можно перетаскивать за заголовок и изменять его размер. Вкладки: **VISUALS** и **CONFIG**. Закрытие меню крестиком также включает click-through.

| Клавиша | Действие |
|---|---|
| Insert | Меню / click-through |
| F1 | Все визуальные элементы |
| F2 | Survivors |
| F3 | Killer |
| F4 | Generators |
| F5 | Hooks |
| F6 | Exit Gates |
| F7 | Имена |
| F8 | Дистанции |
| End | Выход |

Клавиши опрашиваются по переходу «отпущена → нажата». Они работают без фокуса окна overlay и не блокируют получение этих же клавиш другими приложениями. **CONFIG → Save/Load** сохраняет/загружает все визуальные настройки. **Reset defaults** восстанавливает значения в памяти; сохранение выполняется отдельно. Некорректный `config.json` не заменяет текущие настройки; ошибка отображается в меню. Некорректный `offsets.json` или `provider`, отличный от `demo`, приводит к явной ошибке запуска, а не к скрытому использованию демонстрационных данных.

## Camera FOV и направление взгляда demo killer

На вкладке **VISUALS** доступны новые группы **Demo camera** и **Demo killer view** (при необходимости прокрутите меню):

| Настройка | Диапазон / действие |
|---|---|
| Camera vertical FOV | 60–120°, вертикальный угол камеры; по умолчанию 60° |
| Look direction arrow | Стрелка от головы killer, включена по умолчанию |
| View cone (ground sector) | Опциональный горизонтальный сектор на земле, выключен по умолчанию |
| Cone angle | Полный угол сектора 30–120°, по умолчанию 90° |
| Arrow / cone length | Длина стрелки и радиус сектора 1–20 м, по умолчанию 6 м |
| Direction color | Общий RGB-цвет стрелки и сектора |
| Arrow / outline opacity | Непрозрачность стрелки и контура 0–1 |
| Cone fill opacity | Непрозрачность заливки сектора 0–1 |

Увеличение **camera FOV** расширяет видимую сцену. Оно меняет матрицу проекции демопровайдера и не меняет угол сектора killer: это две независимые настройки. Изменения применяются со следующего кадра. Сектор — визуализация направления на горизонтальной плоскости, а не определение видимости, препятствий или окклюзии. Он учитывает общий выключатель ESP, выключатель Killer и предел дистанции. Переключатели стрелки и сектора независимы.

`Entity::lookDirection` — `std::optional<Vec3>` в мировых координатах. Присутствующее направление должно быть конечным единичным вектором; отсутствие направления скрывает соответствующую визуализацию. Только demo killer получает направление: плавный yaw со скоростью 0.35 рад/с. `0` смотрит вдоль `+Z`, положительный yaw поворачивает к `+X`. Стрелка проецирует начало и конец через `WorldToScreen`, сектор — центр и точки дуги. Для точки за камерой или вне near/far соответствующий сегмент пропускается; почти направленная в камеру стрелка без устойчивого экранного направления не рисуется. Вертикальное направление может иметь стрелку, но не имеет горизонтального сектора.

`IDataProvider` не зависит от ImGui, DirectX, renderer или файлов конфигурации: он принимает только `CameraSettings` и aspect ratio. `VisualConfig::camera` передаётся из main; FOV в `demo_provider.cpp` не зафиксирован. `DemoProvider::SampleAt` предоставляет детерминированное время для математических тестов.

**CONFIG → Save** сохраняет новые значения в `config.json`: `camera.vertical_fov_degrees` и поля `visuals.killer_direction`, `killer_cone`, `killer_cone_degrees`, `killer_arrow_length`, `killer_arrow_color`, `killer_arrow_opacity`, `killer_cone_opacity`. Схема остаётся версии 1: старые файлы без новых полей загружаются с указанными значениями по умолчанию. Некорректные новые значения отклоняются без частичного изменения текущих настроек. Все существующие F1–F8, Insert, End и click-through сохранены.

В GitHub выберите ветку `feature/demo-camera-fov-killer-view`, откройте папку `downloads` и нажмите **Download raw file** для `VisualESPOverlay-demo-win64.zip` или `VisualESPOverlay-source.zip`. Исходный ZIP содержит проект без build-каталогов и без вложенных архивов. ZIP Windows содержит exe, offsets.json, README, VALIDATION и лицензии зависимостей. Это кросс-сборка MinGW-w64 x64; для запуска не нужны DLL MinGW рядом с exe.

## Архитектура

```text
IDataProvider::Sample(aspect, CameraSettings) → Frame { Camera, vector<Entity>, source }
                                  ↓
                       RenderEntities / WorldToScreen
                                  ↓
                       ImGui → DX11 → DirectComposition
```

- `include/esp/data_provider.hpp`: единственный контракт источника данных.
- `src/demo_provider.cpp`: тестовые объекты и камера; зависимости от Win32 нет.
- `include/esp/math.hpp`: матрицы, проекция, расстояния.
- `src/overlay.cpp`: Win32, swap chain, прозрачность, ввод, resize, Present.
- `src/renderer.cpp`: визуальные элементы и меню.
- `src/config.cpp`: чтение/сохранение настроек, проверка выбора источника.
- `src/main.cpp`: выбор провайдера, горячие клавиши, цикл приложения.
- `offsets.json`: отдельная схема будущих адресов и структур; неизвестные поля равны `null`.

Внутренний формат: метры, левосторонняя система координат, `+Y` вверх, `+Z` вперёд, row-major хранение матрицы, умножение на вектор-столбец, `clip = projection * view * world`, глубина DirectX `0..w`. Размер viewport передаётся из client area overlay в физических пикселях. Точки за камерой и вне near/far отсекаются; X/Y clipping выполняет renderer. Это не формат памяти Unreal: будущий провайдер обязан преобразовать входные данные в этот контракт.

## Проверки

Portable-тесты проверяют центр и направление проекции, aspect ratio, инверсию Y, near/far, отрицательный/нулевой W, NaN, некорректный viewport, перенос/поворот камеры, расстояния, демоснимок и все пять категорий. Добавлены проверки градусов/радиан, единичного вектора yaw, плавности поворота, углов границ сектора 30/90/120°, длины стрелки, проекции при FOV 60/90/120°, влияния настройки на матрицу и отклонения недопустимого FOV.

При `BUILD_TESTING=ON` и `ESP_BUILD_CONFIG_TESTS=ON` также собирается `config_tests`: сохранение всех новых полей, обратная совместимость, диапазоны FOV/угла/длины/прозрачности, обработка NaN и сохранность состояния при повреждённом JSON. На Windows эта опция включена по умолчанию; portable-сборка без неё выполняет только core_tests без скачивания зависимостей. Команда `ctest --preset release` на Windows запускает оба теста.

На Linux/macOS можно выполнить оба теста без Windows (JSON загружается через HTTPS при первом конфигурировании):

```sh
cmake -S . -B build/core -DESP_BUILD_OVERLAY=OFF -DESP_BUILD_CONFIG_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build/core --parallel 2
ctest --test-dir build/core --output-on-failure
```

Для необязательной кросс-сборки с установленным MinGW-w64 x64:

```sh
cmake -S . -B build/windows -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-x64.cmake -DESP_BUILD_OVERLAY=ON -DBUILD_TESTING=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build build/windows --parallel 2
```

После получения зависимости JSON можно отдельно запустить тот же тест конфигурации нативным Linux-компилятором:

```sh
g++ -std=c++20 -O2 -Iinclude -Ibuild/windows/_deps/json-src/include tests/config_tests.cpp src/config.cpp -o build/core/config_tests_native
./build/core/config_tests_native
```

Ручная проверка графики на Windows:

1. Запустить exe: фон рабочего стола виден, отображаются все пять категорий и метка DEMO; объекты движутся.
2. На VISUALS изменить цвета/дальность, проверить F1–F8 и подписи.
3. Изменить Camera FOV от 60 до 120°: объекты смещаются к центру, угол сектора killer не меняется. Включить сектор, проверить плавный поворот вместе со стрелкой, угол 30/120°, длину 1/20 м, цвет и прозрачность 0/1.
4. Нажать Insert и кликнуть по окну другого приложения под overlay: оно получает клики. Снова Insert: меню принимает ввод.
5. На CONFIG сохранить настройки, изменить их, загрузить и проверить восстановление; повторить после перезапуска.
6. Изменить разрешение монитора и проверить размер окна; завершить клавишей End.

Компиляция Windows exe на Linux не проверяет DWM, DirectComposition, обработку мыши или отображение драйвером. Их проверяет указанный ручной сценарий на Windows. Состояние выполненных проверок зафиксировано в `VALIDATION.md`.

## Поля для будущего реального источника

Рендереру достаточно согласованного `Frame` со следующими данными:

| Данные | Назначение |
|---|---|
| Стабильный ID объекта | Идентификация объекта внутри снимка |
| Категория | Survivor, Killer, Generator, Hook или ExitGate |
| Имя в UTF-8 | Подпись персонажа/объекта |
| Мировая позиция | Ноги персонажа либо точка маркера, в метрах |
| Мировая верхняя точка | Голова/верх для рамки персонажа; не требуется маркерам |
| Необязательный нормализованный lookDirection | Стрелка и горизонтальный сектор; отсутствие скрывает их |
| Позиция камеры | Расчёт дистанции |
| Матрица view-projection 4×4 | World-to-screen в принятом формате |
| Viewport камеры | Согласование aspect ratio, разрешения, letterboxing и screen origin |
| Статус/время снимка | Отбрасывание устаревших данных до выдачи `Frame` |

Если источник будет читать структуры процесса, дополнительно потребуются подтверждённые значения для полей `offsets.json`:

- Точное имя процесса и модуля, fingerprint исполняемого файла/сборки. Проверять перед использованием адресов; метки версии недостаточно.
- RVA корней мира и камеры относительно базы модуля и цепочки разыменований. Адреса должны учитывать ASLR; абсолютные адреса нельзя считать постоянными.
- Формат коллекции объектов: указатель data, поле count, stride, прямые структуры либо указатели, предел допустимого count.
- Смещения ID, категории, имени, позиции, верхней точки и признаков валидности; тип/размер каждого поля и правила определения категории.
- Формат строк: кодировка, указатель/inline данные, длина, предел длины.
- Смещения позиции камеры и view-projection, либо параметры для построения этой матрицы: view/rotation, FOV, aspect, near/far, handedness, порядок и транспонирование.
- Единицы координат и оси, при необходимости относительные transform/родители и преобразование в world space.
- Правила согласованного чтения, определения завершения матча/смены мира и инвалидирования указателей.

Это перечень необходимой информации, а не известная схема DBD. Значения `null` нельзя трактовать как смещение `0`. Текущий `ValidateOffsets` проверяет только версию схемы и выбор demo; будущий реальный провайдер должен отдельно проверять все используемые поля.

Для подключения: реализовать `IDataProvider`, нормализовать данные в описанный формат и явно заменить выбор `DemoProvider` в `src/main.cpp`. Если `provider` в JSON переключается на будущий реальный источник, необходимо одновременно реализовать его создание и полную валидацию конфигурации. Демопровайдер нельзя использовать как автоматическую замену при ошибке реального источника.
