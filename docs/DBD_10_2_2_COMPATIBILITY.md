**Совместимость с реальной DBD 10.2.2 не установлена. В доступной среде не обнаружены установленный клиент, процесс, диагностические файлы или подтверждённый пространственный поток игры. ## Защита процесса: наблюдения и пределы вывода

Наблюдаемых отказов OpenProcess/VirtualQueryEx/ReadProcessMemory **для DBD нет**, поскольку нет целевого процесса. Наличие Easy Anti-Cheat в запущенной сборке, версия его модуля, параметры защищённого старта и выданные/отобранные handle rights не установлены. Выключение защиты или изменение игровых файлов не выполнялись.

Существующий ProcessReader запрашивает `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`, проверяет identity/AMD64 PE, читаемость страниц и точный результат RPM. Это подтверждено на стенде. Для будущего настоящего отказа нужен фактический журнал операции, PID/build, адреса/размера, code и transferred bytes:

| Возможный будущий результат | Что он устанавливает | Чего одного этого результата недостаточно установить |
|---|---|---|
| OpenProcess, ERROR_ACCESS_DENIED (5) | Запрошенный handle не получен | Античит как единственную причину: возможны DACL, integrity/privilege или иные ограничения процесса |
| RPM, ERROR_PARTIAL_COPY (299) | Не получен полный запрошенный диапазон | Стабильность layout или причину: возможны изменение mappings, уход объекта/процесса, недоступные страницы |
| Проверка страницы / ERROR_NOACCESS (998) | Диапазон не соответствует требованию read-exact | Что адрес правильный или что отказ вызван конкретной защитой |
| Неверный module fingerprint | Конфигурация и наблюдаемый PE не совпадают | Точную семантическую версию игры без проверенных build metadata |
| Доступное чтение, но invalid Frame | Контракт/значения не прошли decoder validation | Наличие корректных пространственных данных в другом месте |

Эта таблица описывает интерпретацию возможных диагностик, а не результаты проверки реальной игры. Никакие права не повышались, обход или сокрытие не добавлены.

## Сопоставление с MemoryLayout и GameStateDecoder

Ни одно пространственное поле ниже не получено из DBD. Полный машинный перечень с `confirmed_dbd_value: null`: [dbd-3-compatibility.json](dbd-3-compatibility.json).

| Поле / группа | Текущий decoder | Данные DBD 10.2.2 и требуемая работа |
|---|---|---|
| Build identity / корень | Имя exe/module, AMD64, image_size + pe_timestamp; data export либо RVA и ≤8 pointer hops | Неизвестны. Нужны фактический клиент, PE fingerprint и подтверждённое владение корнем. Имя `EspFixtureState` относится исключительно к стенду |
| Согласованность / время | Встроенные magic/version, выровненная uint64 revision с even/odd protocol, uint64 sequence/timestamp_us | Наличие таких полей у игры не подтверждено. Нельзя подставить фиктивный revision. Требуется документированная модель согласованного снимка |
| Коллекция объектов | count и непрерывный массив фиксированного stride: inline или один uint64 pointer | Родной игровой контейнер не известен. Список указателей/разные структуры классов не выражаются одним stride; потребуется подтверждённое декодирование структуры при наличии источника |
| ID и категории | Уникальный uint64 ID и uint32 kind с пятью mappings | Ни значения, ни layout не подтверждены. Адрес объекта без правил жизненного цикла не является установленным устойчивым ID |
| Имена | Fixed-size UTF-8 buffer с NUL | Реальная кодировка/представление неизвестны; indirect/UTF-16/string table потребовали бы подтверждённого преобразования |
| Survivors / killer | float32 position и top | Реальных координат/верхней точки нет. Верхняя точка требует настоящих bounds/transform; постоянная высота не заменяет измерение |
| Generators / hooks / gates | Те же float32 positions, отдельные kind mappings | Координаты экземпляров конкретного матча отсутствуют; справочник карты этого не даёт |
| Killer look | Frame допускает отсутствие direction; layout при этом требует физические direction/flags slots и nonzero mask | Наличие этих полей неизвестно. Источник без направления не даёт стрелку/сектор; отсутствие физических slots нельзя исправить выдуманным смещением |
| Camera / VP | Позиция и 16 float32 прямо в header | Реальная камера/матрица отсутствуют. Раздельные pointers, float64, pose-only или другие conventions требуют отдельного подтверждённого преобразования |
| Координатный контракт | Метры, LH, +Y up, +Z forward, row-major VP × column vector, clip z 0..w | Реальная система DBD не измерена. Нельзя автоматически приписать ей centimetres/Z-up или выбранный matrix order |

**Дополнительное наблюдение по коду:** LiveFrameSource разрешает `root_`/pointer chain внутри `if (!process_.Alive())`. Чтение повторяется, но адрес корня не перечитывается на каждом кадре. Если будущий источник сменит корень при том же PID и старая память останется читаемой, возможен stale без повторного разрешения корня до restart/Apply/read failure. На стенде корень стабилен. Использует ли DBD такой жизненный цикл — неизвестно; это обязательная проверка будущего реального источника, а не заявленный баг DBD.

Текущий decoder поддерживает конкретный контракт. Его работоспособность на стенде не означает, что произвольный game object graph можно подключить заполнением JSON. `offsets.json` с null остаётся неиспользуемым, а fixture layout не переименован в DBD layout.

### Преобразования при появлении подтверждённого источника

Точные коэффициенты/перестановки пока выбрать нельзя. Понадобятся: подтверждённые units/axes/handedness, mapping типов и ID, decoding имён и bounds, camera convention/viewport, time/session semantics и consistency protocol.

Для известного преобразования базиса/единиц `p_target = T * p_source` согласованная камера при одинаковом clip convention задаётся `VP_target = VP_source * inverse(T)` после приведения исходной матрицы к column-vector convention. При отличающемся clip-depth требуется ещё подтверждённое преобразование clip-space. Направление преобразуется линейной частью T и нормализуется. Нельзя менять только координаты, оставляя VP в прежнем базисе, либо применять Demo FOV к неизвестной live camera.

Интеграция возможна только после получения реального контракта и образцов: адаптация декодирования в существующем LiveFrameSource/RuntimeDataProvider, полная ValidateFrame и проверка настоящей сессии. Новый worker, renderer и имитационный DBDDataSource не созданы.

## Оставшиеся препятствия и проверяемое завершение

1. **Нет наблюдаемой установки/сессии.** Для проверки точной версии нужны реальные executable version resources и launcher/store manifest; для архитектуры и модулей — фактический PE и process/module inventory. Версия приложения overlay и Steam build ID этому не равны.
2. **Нет подтверждённого пространственного producer contract.** Нужны актуальная документация/условия доступа, sample текущего матча и поля всех требуемых сущностей/камеры. Из этой среды origin docs недоступны из-за proxy CONNECT 403.
3. **Доступ к защищённому процессу не измерен.** Нужны реальные результаты существующего read-only reader на правильном target. Сейчас нельзя заключить ни ACCESS_DENIED, ни успешный доступ к DBD.
4. **Родной layout и consistency не известны.** Требуется сопоставить настоящее представление с ограничениями таблицы; подобрать offsets без данных невозможно. Самого успешного RPM недостаточно.
5. **Нет end-to-end реальной игровой проверки.** Нужно сравнить текущие координаты/камеру и жизненный цикл с реальной сессией, включая смену карты/корня, исчезновение, restart, age и provenance. Ни один тест со стендом этот пункт не закрывает.

Проверки текущего этапа и неизменность runtime зафиксированы в compatibility JSON и VALIDATION.md. Рабочие режимы версии 2.0 сохранены. Поддержка DBD 10.2.2 не объявлена.
